# Connecting ComfyUI to Open WebUI — the organization's image server

Demo code for module 1 of the "Click by Click" series **Image generation in Open WebUI with
ComfyUI**: Open WebUI users generate images on the organization's graphics card, without sending
their requests to an outside service.

Video: {{video}}

## Goal

- **ComfyUI** runs in a container, on the machine with the graphics card (`comfyui/`), with an
  image model under the Apache 2.0 license (Z-Image Turbo, 8 steps).
- Its **workflow** is exported in **API format** (`workflows/text-to-image.json`): a dictionary,
  one entry per node number, whose values Open WebUI fills in for each request.
- **Open WebUI** is connected in Admin Panel › Settings › Images: internal address of ComfyUI,
  workflow, node mapping, model, size, steps (`open-webui/images-settings.md`, or
  `setup_images.py`).
- In a chat, the user turns on "Image"; the chat model writes the description and calls the
  `generate_image` tool; the image computed by ComfyUI is stored among Open WebUI's files.

| File | Content |
|---|---|
| `comfyui/Dockerfile` | Image `comfyui:1`: Python 3.13, PyTorch 2.14.1 (CUDA 13.0), ComfyUI v0.41.0, no custom node |
| `comfyui/k8s.yaml` | Deployment (one replica, `Recreate`: a single card), service `comfyui:8188`, interface published through an Ingress |
| `workflows/text-to-image.json` | Workflow in **API format**, as exported in the video (to upload into Open WebUI) |
| `workflows/text-to-image.interface.json` | The same workflow in ComfyUI's interface format (to open in ComfyUI): Comfy-Org template "Z-Image Turbo int8", subgraph unpacked keeping the numbers 27, 28, 13, 3, 9 |
| `open-webui/images-settings.md` | Every field of the Images page, the node mapping and its two traps |
| `setup_images.py` | The same settings through Open WebUI's API (Python standard library), test, rollback |

The French video shows the same files with French node titles and comments (`texte-vers-image.json`);
this repository holds their English version, same structure, same node numbers.

## Prerequisites

- A machine with an NVIDIA graphics card (8 GB is enough), Kubernetes with the `nvidia` runtime
  (filmed on k3d, a cluster dedicated to the card), `kubectl`, Docker.
- Open WebUI 0.11 (filmed on 0.11.3) able to reach ComfyUI over the cluster network, an
  **administrator** account, and a chat model able to call tools.
- The model weights, in the volume mounted on `/modeles/comfyui/models` (6.2 + 5.6 + 0.3 GB):

| Folder | File | Source (Hugging Face, Apache 2.0) |
|---|---|---|
| `diffusion_models/` | `z_image_turbo_int8_convrot.safetensors` | `Comfy-Org/z_image_turbo` › `split_files/diffusion_models/` |
| `text_encoders/` | `qwen_3_4b_fp8_mixed.safetensors` | `Comfy-Org/z_image_turbo` › `split_files/text_encoders/` |
| `vae/` | `ae.safetensors` | `Comfy-Org/z_image_turbo` › `split_files/vae/` |

## Step by step

### 1. The image server

```bash
docker build -t comfyui:1 comfyui            # a few GB: PyTorch CUDA
k3d image import comfyui:1 -c <cluster>      # no registry (or push the image to yours)
kubectl apply -f comfyui/k8s.yaml
kubectl -n comfyui rollout status deploy/comfyui
```

Adapt `k8s.yaml` to your cluster: Ingress host name, model volume (`hostPath` here). ComfyUI's
interface must be open to administrators only: it has no accounts.

### 2. The workflow, in ComfyUI

Open `workflows/text-to-image.interface.json` (drag and drop it onto the interface, or
`python setup_images.py --comfyui`, which stores it in the "Workflows" panel). Find the nodes by
their number (in Settings, search for "badge": Node ID badge mode, "Show all"), then menu
**File › Export (API)**: Open WebUI expects this file, not the interface format.

### 3. Open WebUI, by hand as in the video

Admin Panel › Settings › Images: follow `open-webui/images-settings.md` (turn on, ComfyUI engine,
"Base URL", verify, upload the workflow, node mapping, model, size, steps, save).

### 3b. Open WebUI, through the API

```bash
cp .env.example .env               # OWUI_URL, OWUI_TOKEN (administrator), COMFYUI_URL…
python setup_images.py             # backs up the current configuration (images-config.backup.json), then applies
python setup_images.py --test      # a test image, generated by Open WebUI
python setup_images.py --restore   # back to the saved configuration
```

The Images page is a setting of **the whole instance**: `images-config.backup.json` keeps the
previous configuration, keys included (file ignored by git, do not share it).

## Try it

With a user account: new chat, "Integrations" menu › "Image", then "A poster for the Workplace
Safety training in Lyon: a hard hat and a yellow vest, illustration style, bright colors, no
text." (the image model often mangles words written in the image). Unfold the `generate_image`
call: the description sent to ComfyUI was written by the chat model. A second request gives a new
image (new seed).

## Security

- ComfyUI has neither accounts nor key: expose its service to Open WebUI only (cluster network) and
  its interface to administrators only.
- No request leaves the organization: description, computation and image stay in the cluster.
- No secret in this repository: `.env` and `images-config.backup.json` are ignored by git.
